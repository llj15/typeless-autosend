# 端到端测试用例：离开即发送

对应方案：[design-leave-to-send.md](design-leave-to-send.md)
用途：改造完成、安装到真机后，人工逐条验证。用例不绑定具体应用，只按输入框类型分类。

状态：本次开发未执行这些真机用例。实现和单元测试的边界见 [implementation-notes-leave-to-send.md](implementation-notes-leave-to-send.md)；同应用换窗口立即按原 PID 投递，缓冲内离开则等定位完成。原生接收窗口、控件和处理顺序尚待验证；点击关系不确定时不提前发送。以下用例保留为后续人工验证清单，不代表已经验证。

## 测试环境

| 类型 | 特征 | 记作 |
|---|---|---|
| 普通输入框 | 输入框的值只有用户输入的文字，报告光标位置（如聊天应用的消息框） | 【普通】 |
| 整屏输入框 | 输入框的值是整屏文字，屏幕会自行刷新，不报告光标（如终端） | 【整屏】 |

准备：
1. 两类应用各准备一个，加入白名单：`typeless-autosend apps add <bundle-id>`
2. 延迟设为 3 秒，方便操作：`typeless-autosend delay set 3`
3. 另开一个窗口实时看日志：`tail -f ~/typeless-autosend/autosend.log`
4. 【整屏】准备一个会自行刷新的界面（如带计时器或状态栏的 TUI），并在屏幕上方留有历史输出
5. 【整屏】测试时输入行内容用无害命令，如 `echo e2e-ok`；【普通】使用测试会话，避免误发到正式对话

当前日志约定：

| 结果 | 日志 |
|---|---|
| 到点发送 | `enter id=… destination=original-pid` |
| 同应用点框外先发送 | `enter id=… destination=before-focus-change` |
| 同应用焦点已切换到其他窗口或输入框 | `enter id=… destination=original-pid` |
| 原应用失去前台后发送 | `enter id=… destination=original-pid` |
| 中断 | `skip id=… <原因>` |

每条用例默认在【普通】【整屏】各跑一次，标注"仅【整屏】"的除外。

## A. 基础发送

| # | 操作 | 预期 |
|---|---|---|
| A1 | 说一句话，之后不动 | 粘贴缓冲结束后等待 3 秒再回车；`destination=original-pid` |
| A2 | 输入框里已有文字，在末尾说一句话，之后不动 | 3 秒后回车，提交的是完整内容 |
| A3 | 把光标放在已有文字中间说一句话，之后不动 | 3 秒后回车（【普通】按插入点定位） |
| A4 | 延迟设为 0，说一句话 | 粘贴缓冲（150ms）后立即回车 |

## B. 中断（不发送）

| # | 操作 | 预期 |
|---|---|---|
| B1 | 说完后在倒计时内删掉一个字 | 不发送；`skip` 原因为基准区域变化 |
| B2 | 说完后在倒计时内补打几个字 | 不发送 |
| B3 | 说完后用方向键左移光标 | 【普通】不发送，原因为光标变化；【整屏】光标不可见，到点照常发送 |
| B4 | 说完后用鼠标在原输入框里点一下，挪动光标 | 【普通】不发送；【整屏】到点照常发送 |
| B5 | 说完后在倒计时内再按一次听写快捷键开始新一轮 | 旧的一次不发送，原因为新一轮听写；新的一轮完成后正常倒计时 |
| B6 | 用非 Fn 的自定义快捷键触发听写，重复 B5 | 同 B5，与快捷键无关 |
| B7 | 说完后执行 `typeless-autosend service pause` | 不发送；恢复后也不补发 |
| B8 | 说完后把该应用移出白名单 | 不发送 |
| B9 | 说完后在倒计时内退出原应用 | 不发送 |

## C. 不中断（倒计时继续）

| # | 操作 | 预期 |
|---|---|---|
| C1 | 说完后单按 Shift / Cmd / Option / Ctrl | 到点发送 |
| C2 | 说完后按 Cmd+C 等不改文字的组合键 | 到点发送 |
| C3 | 说完后用鼠标点原输入框，光标位置不变（点在文字末尾） | 到点发送 |
| C4 | 说完后移动鼠标、滚动页面 | 到点发送 |
| C5 | 仅【整屏】：说完后等屏幕计时器、状态栏自行刷新 | 到点发送，不因刷新取消 |
| C6 | 仅【整屏】：说完后让上方历史区域有新输出（如另一进程打印日志） | 到点发送 |

## D. 立即发送：同应用内离开

| # | 操作 | 预期 |
|---|---|---|
| D1 | 粘贴缓冲结束后点消息区 / 历史输出区 | 目标可确认为框外时先调用回车投递，再放行点击；`destination=before-focus-change`；需真机确认应用处理顺序 |
| D2 | 粘贴缓冲结束后点窗口空白处 | 能确认框外时同 D1；只命中原窗口或关系未知时不提前发送 |
| D3 | 仅【整屏】：粘贴缓冲结束后点同窗口的另一个分屏 | 能确认框外时先投递到原进程再放行点击；真机确认回车是否落在原分屏 |
| D4 | 粘贴缓冲结束后点同窗口里的另一个输入框 | 能确认框外时先投递回车，再放行点击；真机确认接收控件与顺序 |
| D5 | 粘贴缓冲结束后点按钮或下拉框 | 能确认框外时先投递回车，再放行点击；真机确认按钮处理顺序 |
| D6 | 说完后用快捷键切到同应用的另一个窗口 | 立即按原 PID 投递回车；`destination=original-pid`；真机确认原窗口是否提交及新窗口是否受影响 |
| D7 | 说完后在 150ms 内点框外（几乎同时） | 等缓冲完成、读取原输入框并定位后投递；焦点已切换不取消；真机确认接收控件和点击处理顺序 |
| D8 | 同窗口同时打开主输入框和消息编辑输入框；在主框听写后点击编辑框 | 先向原进程投递回车，再放行点击；旧框失焦后选区清零不应取消；真机确认提交的是主框 |
| D9 | 输入框的辅助功能文字延迟刷新，粘贴后立刻离开 | 有界等待原框文字刷新，定位成功后仅投递一次；超时仍无粘贴效果则跳过 |

## E. 立即发送：切到别的应用或桌面

| # | 操作 | 预期 |
|---|---|---|
| E1 | 说完后立刻点别的应用的窗口 | 未确认原输入框编辑时后台回车；`destination=original-pid`；不等满 3 秒 |
| E2 | 说完后立刻点 Dock 图标 | 同 E1 |
| E3 | 说完后立刻四指滑到别的桌面 | 同 E1；滑回来看到已提交 |
| E4 | 说完后立刻 Cmd+Tab | 同 E1 |
| E5 | 说完后立刻用启动器快捷键（Spotlight 等）打开别的应用 | 同 E1 |
| E6 | 四指滑到一半缩回来，没真切走 | 不触发立即发送，到点照常发送 |
| E7 | 切走后在别的应用里打字 | 不影响，原应用已提交，别的应用里的输入正常 |
| E8 | 切走后很快又切回原应用 | 原应用已提交，不会重复回车 |

## F. 定位

| # | 操作 | 预期 |
|---|---|---|
| F1 | 仅【整屏】：历史里已有 `ok`，再说"ok"，然后等屏幕刷新 | 到点发送，不因历史行或状态栏误判 |
| F2 | 仅【整屏】：状态栏里含有转写文字的子串（如说"ok"，状态栏显示 `tokens`），等状态栏刷新 | 到点发送 |
| F3 | 说一句超过窗口宽度、会折行的长句，之后不动 | 到点发送 |
| F4 | 说一句很长、输入框会折叠显示（如显示成"粘贴了 N 行"）的内容 | 定位不了，按整个输入框比对：【普通】到点发送；【整屏】屏幕刷新可能取消，与当前 main 一致 |
| F5 | 开口时在 X 应用，说话过程中切到 Y 应用（Y 在白名单），文字粘进 Y | 按 Y 定位；之后按 A/D/E 的规则发送 |
| F6 | 开口时在 X 应用，说话过程中切到 Y 应用（Y 不在白名单） | 不发送；`skip` 原因为不在白名单 |
| F7 | 仅【整屏】：说话过程中切到同窗口的另一个分屏，文字粘进新分屏 | 按新分屏定位并发送 |

## G. 系统状态

| # | 操作 | 预期 |
|---|---|---|
| G1 | 说完后进入密码框（触发 Secure Input） | 不发送 |
| G2 | 撤销辅助功能权限后说一句话 | 不发送；`service status` 显示权限不可用 |
| G3 | 恢复权限、重启服务后说一句话 | 正常发送 |
| G4 | 连续说两句，第二句在第一句倒计时内完成 | 第一句不发送（被新一轮取代），第二句正常 |
| G5 | 服务重启后说一句话 | 正常发送；重启前未完成的不补发 |
