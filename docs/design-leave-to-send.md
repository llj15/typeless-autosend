# 改造方案：离开即发送

基线：`main` @ `5a2f77c`（PR #6 focus-aware-autosend 合并后）
分支：`feature/leave-to-send`
日期：2026-10-23

## 核心思想

只有用户改了刚转写的那段文字才取消；用户一离开原输入框就立即发送；一直停在原输入框里不动，才等满倒计时。

现在 `main` 的思路是"无法确认安全就不发"：按键、屏幕刷新、切走、到点时读不到输入框，都会取消，导致大多数正常场景发不出去。本方案改为"只有确认用户改过才不发"。

## 三条原则

1. **判据只看内容**：粘贴进去的那段文字或光标变了，才算改过。按键、点击、切换应用本身都不算。
2. **离开即发送**：同应用里点别处（拦住点击、先发回车）、切到别的应用或桌面，立即发回车。同应用里光标已经离开原输入框（换输入框、换窗口）则取消，不补发：按进程发的回车会落到新焦点上。
3. **到点只确认光标**：倒计时期间一直在实时监听；到点时原应用若在前台，确认光标仍在原输入框再发，否则取消。

代码中不出现任何具体应用名称或按键键位。

## 流程

```
① 触发与定位
   监听到 Typeless 进程发出的 Cmd+V（放行前）
   → 读当前前台输入框：快照 A（文字和光标读数）
   → 放行，文字粘贴进去
   数据库出现 completed 的新转写，150ms 粘贴缓冲结束
   → 读同一输入框：快照 B；记下原应用 PID、输入框对象，B 的光标读数作为光标起点
   → 基准区域 = 粘贴进去的那段文字所在的行；只按 A、B 的文字定位，不用光标读数当文字坐标
     （实测有应用报的光标位置不计入值里的部分字符，按它定位会把正常追加判成被改）
       · B 正好是 A 的唯一一处被替换（或插入）成原文：直接按这个位置定位；有多个合法位置时比较整个输入框，不再任选一个位置
       · 否则先要求原文出现次数增加，再把 A、B 按内容对齐；只有历史同文和其他区域刷新时继续等待，超过粘贴缓冲期限仍未观察到新增证据则取消
       · 都定位不了：基准区域取整个输入框（与当前 main 一致）
       · A、B 文字完全相同时例外：必须验证原选区范围有效、所选文字等于转写内容、粘贴后选区归零且光标到预期末尾；用该选区定位，否则继续等待，不把历史同文当作粘贴成功

② 中断（永久取消，不发送）
   a. 基准区域的文字变了
   b. 光标读数离开了 B 的光标起点（只和读数比，不和文字长度比；应用不报告光标时不触发；粘贴缓冲内的光标变化不检查）
   c. 数据库出现一条更新的记录（新一轮听写开始，不论状态）
   d. 原应用退出 / 权限丢失 / 进入 Secure Input
   a、b 只在原应用在前台时检查

③ 立即发送（离开原输入框）
   a. 同应用内点原输入框以外的地方（消息区、空白、其他分屏、其他控件）
      → 拦住点击 → 先发回车 → 再放行点击
   b. 同应用内光标已离开原输入框（换输入框、换窗口）
      → 取消，不补发（此时按进程发的回车会落到新焦点）
   c. 原应用失去前台（点别的应用、Dock、触控板手势、任何快捷键）
      → 立即后台按进程发回车
   离开发生在 150ms 缓冲内的，等缓冲结束、定位完成后再发

④ 不处理（倒计时继续）
   · 按键事件本身（是否改了内容由 ②a、②b 判定）
   · 点原输入框里面但光标没动

⑤ 到点
   一直停在原输入框里没动 → 发回车
```

## 与当前 main 的行为差异

| 场景 | 当前 main | 本方案 |
|---|---|---|
| 判断"原框被改过" | 任意按键即算；整个输入框的值变化即算 | 只看粘贴进去的那段文字所在区域和光标 |
| 定位粘贴位置 | 不定位 | 抓 Typeless 的 Cmd+V，放行前后各读一次输入框 |
| 输入框的值包含整屏内容（如终端） | 屏幕刷新被误判为编辑，取消 | 只看基准区域，其他区域刷新不影响 |
| 屏幕上已有相同文字（如历史里的 `ok`） | 不涉及 | 按"粘贴前没有、粘贴后有"定位，不会选到历史行 |
| 说着话切到别的应用或分屏 | 不涉及 | 定位以 Cmd+V 那一刻的前台为准，不受影响 |
| 新一轮听写 | 只识别 Fn 键 | 数据库出现新记录即算，与快捷键无关 |
| 同应用点消息区、空白处 | 取消 | 先回车，再放行点击 |
| 同应用点另一个分屏 | 取消（控件不报告 AXEnabled） | 先回车，再放行点击 |
| 点原输入框里面、光标没动 | 取消 | 不处理 |
| 点别的应用、AX 命中测试失败 | 取消（`cannot classify mouse target`） | 原应用失去前台，立即发送 |
| 切到别的应用或桌面 | 倒计时继续；到点重读输入框，常因读不到或内容变化而放弃 | 立即后台发送 |
| 到点 | 重读输入框比对文字和选区 | 只确认未中断、PID 存活 |
| 发送方式 | `postToPid` | 不变 |

## 代码改动

| 位置 | 当前 | 改为 |
|---|---|---|
| `InputMonitor.handle`：Typeless 来源的按键 | 识别为 Typeless 后直接放行 | 识别到 Typeless 的 Cmd+V 时，放行前读前台输入框，存为快照 A 和插入点 |
| `InputMonitor.handle` 键盘分支 | 前台任意按键即取消；Tab、Cmd+Tab 特判 | 删除，按键不再作为判据 |
| `InputMonitor.handle` Fn 判断 | Fn 即取消 | 删除；改为 `main.swift` 轮询数据库时发现更新的记录即中断 |
| `InputMonitor.handle` 鼠标分支 | 先做 AX 命中测试，失败即取消；只有点"可用的文本框"才先回车 | 只处理原应用在前台时的点击；点的不是原输入框（也不是其祖先或子元素）→ 先回车再放行 |
| `mouseDecision` / `separateEditableTarget` | 要求 AXEnabled、可聚焦、角色为文本框 | 简化为"是否原输入框"判断 |
| `settleAttempt` | 锁定整个输入框的值和选区 | 用快照 A、B 计算基准区域并锁定 |
| AX 内容/选区变化通知 | 整个输入框的值变化即取消 | 只比对基准区域和光标 |
| `handleFocusNotification` | 焦点变化或读不到即取消 | 同应用内焦点离开原输入框（换输入框或换窗口）→ 取消，不补发（按 PID 发的回车会落到新焦点）；原应用在后台时忽略 |
| 新增：原应用失去前台 | 无 | 监听 `NSWorkspace.didDeactivateApplicationNotification`，命中原 PID → 立即 `postToPid` |
| `main.swift` 定时器（每 100ms） | 调 `validateAttempt` 重读整个输入框，不一致即取消 | 改为只在原应用在前台时比对基准区域和光标 |
| `main.swift` 数据库轮询 | 只读 `completed` 记录 | 倒计时期间，任意状态的更新记录出现即中断 |
| `deliver`（到点） | `validateAttempt` 重读比对 | 确认未中断、PID 存活；原应用在前台时再确认焦点仍在原输入框，否则取消；然后发回车 |

不变：数据库触发、150ms 粘贴缓冲、`postToPid` 发送方式、暂停和恢复、权限与 Secure Input 检查。

## 已验证的前提（2026-10-22 至 23 实测）

| 前提 | 结果 | 说明 |
|---|---|---|
| Typeless 用 Cmd+V 粘贴 | ✅ | 先写剪贴板，再以 Typeless 进程发出 Cmd+V（键码 9 + ⌘）；事件监听能在交给目标应用前收到并识别来源；约 2 秒后剪贴板被恢复 |
| 后台按进程发回车，终端类应用 | ✅ | 应用在后台，回车后命令执行 |
| 后台按进程发回车，Chromium 内核应用 | ✅ | 回车能触发提交；普通字符在后台不会插入 |
| 听写开始时数据库立即写入记录 | ✅ | 开口约 0.1 秒内插入，`status` 为空，完成后变为 `completed` |
| 切换应用或桌面时能收到"失去前台"通知 | ✅ | 触控板四指切桌面时收到 `DEACTIVATED` |
| 输入框的值包含整屏内容 | ✅ 已确认 | 终端类应用暴露单个 `AXTextArea`，值为整屏文字，空闲时也在变化，选区恒为 `0,0` |
| 数据库能否提供粘贴位置 | ❌ | `audio_context`、`debug_info` 加密，其余字段无位置信息，因此改为抓 Cmd+V |

注意：用临时编译的测试程序发送按键时，必须单独授予辅助功能权限，并通过 `launchctl submit` 以独立进程启动；从终端直接启动时，即使系统接口报告有权限，事件仍可能被丢弃。重新编译会使授权失效。

## 测试

单元测试（`tests/test_runtime.py`）：每条规则至少一个用例。

| 规则 | 用例 |
|---|---|
| ① 定位 | B 是 A 的干净插入或替换：按文字算出的位置定位，即使应用报的光标位置有偏差 |
| ① 定位 | 不是干净插入：屏幕已有相同文字时，选中新出现的那一行 |
| ① 兜底 | 定位不了时比对整个输入框 |
| ②a | 基准区域文字变化 → 取消 |
| ②a 反例 | 基准区域以外的内容变化 → 不取消 |
| ②b | 光标位置变化 → 取消 |
| ②c | 数据库出现更新的记录 → 取消 |
| ③a | 同应用点原框以外 → 先发送，再放行点击 |
| ③b | 同应用内光标离开原输入框（换输入框、换窗口）→ 取消，不补发 |
| ③c | 原应用失去前台 → 立即后台发送 |
| ③ 缓冲 | 150ms 缓冲内点框外 → 暂扣点击，缓冲结束后先发送再放行；缓冲内光标已离开 → 取消 |
| ④ | 按键但内容不变 → 不取消；点原框且光标不动 → 不取消 |
| ⑤ | 停留不动 → 到点发送 |
